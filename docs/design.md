# Windows 邮件小秘书方案

## 目标

为妈妈的 Windows 10/11 电脑制作中文图形程序。她已有并在使用 Codex，程序沿用她电脑上的 Codex 登录状态。只在发现新邮件时调用 AI，逐封生成六项 TXT 报告；空检查不调用 AI。

## 使用界面

首次打开填写 163 邮箱地址和客户端授权码，选择报告保存文件夹。自动查找本机 Codex；找不到时显示“选择 Codex 程序”，给出具体操作提示。

首页包含：

- 清晰的状态卡：运行中、已暂停、网络中断或需要重新登录。
- “开始／暂停”按钮。
- “测试连接”按钮，分别说明邮箱和 Codex 是否可用。
- “打开邮件文件夹”按钮。
- 最近生成的报告列表。
- “登录 Windows 后自动启动”开关。

关闭窗口时可继续在托盘运行。托盘菜单提供打开窗口、暂停、退出。提示用自然中文，不把堆栈或技术日志显示给妈妈。

## 邮件与报告

复用已经验证的 IMAP 客户端标识、只读读取和 UID 去重逻辑。第一次配置时记录现有邮件位置，不把全部旧邮件重新分析。断网或关机后恢复时补查积压来信。

默认报告路径：当前用户的“文档／邮件／日期／标题-收到时间.txt”。实际 Windows 文档文件夹通过系统接口解析，兼容 OneDrive 重定向。按北京时间命名；目录不存在时自动创建，重名时增加编号。

每封报告包含：新邮件提醒、发件人、中文摘要、具体待办及截止时间、附件实际内容、可复制的建议回复。打不开的附件说明限制。不会自动回复，不会改变邮件已读状态。

使用不保留会话的 `codex exec --ephemeral`，不直接续写妈妈桌面正在使用的聊天，避免此前的写入冲突。AI 结果先缓存，保存失败时重试导出，不重复调用 AI。

## 本地资料

邮箱授权码通过 Windows DPAPI 加密，绑定当前 Windows 用户，保存在本地应用数据目录。配置、进度和报告不打包进发布文件，不上传 GitHub。Codex 凭据由 Codex 自己管理，程序不复制它们。

邮件和附件只作为数据；不执行附件、宏或来信中的指令。读取来信和附件内容用于 AI 分析时，沿用妈妈已有的 Codex 服务。每次开始监听前明确显示这项用途。

## 技术与交付

Python 邮件核心，Tkinter 中文界面，托盘组件，PyInstaller 打包。最终交付 Windows ZIP，解压后双击 EXE；妈妈无需安装 Python 或打开终端。第一版面向 x64 Windows 10/11。

源代码和自动化测试放入 Benson-YiYan 账号下的私有 GitHub 仓库 `benson-mail-assistant-windows`，待用户确认后创建。Windows 安装包由 GitHub Windows runner 生成。

## 测试与验收

Mac 上执行跨平台核心测试：UID 去重、停止期间补查、目录创建、北京时间转换、非法文件名替换、重名保护、附件提取、AI失败重试及空检查不调用 AI。

GitHub Windows 测试机执行：

1. 图形界面启动、状态切换和关闭行为。
2. Windows 文档目录解析、Unicode 中文路径和文件写入。
3. DPAPI 加密与解密。
4. 注册表自启动配置的写入、读取与撤销。
5. 模拟邮件与模拟 Codex 的完整流程，验证六项报告及去重。
6. 打包后 EXE 的启动自检，并保存测试日志和界面截图。

测试使用虚构邮箱和模拟邮件，真实授权码、客户邮件及妈妈的 Codex 登录信息不传给测试机。

这些测试能验证程序在 Windows 的行为，但不能代替妈妈电脑的真实邮箱网络和 Codex 登录检查。首次配置提供一个“测试连接”按钮，逐项检查真实环境；失败显示原因和明确下一步。
