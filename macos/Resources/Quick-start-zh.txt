邮件小秘书 Mac — 全功能与设置指南

1. 安装与入口
支持 macOS 14 或以上，Apple 芯片与 Intel 分别选择对应 DMG。在“关于本机”查看处理器，把应用拖入“应用程序”后从那里启动，勿直接在只读镜像中运行。无需 Python 或 Homebrew。当前使用临时签名，未 Apple 公证；首次被拦截时，核对下载来源与 SHA256 后按“系统设置 → 隐私与安全性”提供的允许选项处理，不要全局关闭系统保护。
侧栏“邮件报告”用于阅读，“邮箱与检查”管理邮箱和收信规则，“AI 服务”设置模型，“通用设置”管理目录、通知、工具、语言和更新；菜单栏信封可恢复窗口。
首次启动会要求连接邮箱、选择 AI 和报告目录。语言按系统首选项选择：中文用简体中文，西班牙语用西班牙文，其余用英文。没有新邮件和待重试任务时，定时检查不调用 AI；手动测试、问答、草稿、重新总结和历史补总结可能收费。

设置页统一保存：在“邮箱与检查”“AI 服务”“通用设置”中，可连续修改多项；每页底部只有一个“保存”，点击后统一生效。“有未保存的设置”表示改动仍暂存在内存，离开该页会先询问是否放弃。测试连接前先保存。界面语言在通用设置保存成功后切换，未安装的语言包会在保存时询问下载。费用单价在“AI 服务”填写，并随该页一起保存；用量窗口只查看记录。

2. 添加、切换和管理邮箱
进入“邮箱与检查”，在“已添加的邮箱”选择已有账号，或点击“添加邮箱”新建。每个账号独立保存凭据、连接、代理和收信进度；AI、报告目录、检查间隔和屏蔽规则共用。可单独启用／暂停某账号，也可移除账号；移除不会删除已生成的报告或服务器邮件。编辑地址、服务器、用户名、文件夹或凭据前，先暂停全部监听并等当前任务完成。
先在邮箱服务商的网页版开启 IMAP，再选预设。选择“其他邮箱（自定义 IMAP）”可连接企业邮箱等未列出的服务；预设的服务器和端口也可修改。收信和总结通过 IMAP；回复可在明确确认后通过已配置邮箱的 SMTP 发送。
邮箱地址：填完整地址，例如 name@example.com。
IMAP 收件服务器：仅填域名或 IP，例如 imap.example.com；不要加 https://、路径或端口。
端口与加密：通常 SSL/TLS 为 993；STARTTLS 通常为 143，以服务商官方说明为准，勿任意搭配。
密码／授权码／令牌：按服务商要求使用客户端授权码、应用专用密码或 OAuth2 access_token，不是短信验证码、AI Key、refresh_token 或 id_token。修改其他连接信息后可能需要重填凭据；留空只在连接未变且已有匹配密钥时保留旧密钥。
保存邮箱设置后测试连接，成功再恢复监听。“如何获取授权码？”打开各预设的逐步教程及官网；已有 AI 软件也可帮助查找正确流程，但别把凭据贴给它。

3. 高级登录、文件夹和代理
登录用户名默认留空，跟随完整邮箱地址。仅在服务商明确要求不同用户名时填写；填旧账号或昵称可能使正确授权码也无法登录。
邮件文件夹默认 INBOX。只检查所选文件夹，不会自动遍历所有归档、垃圾邮件和标签；文件夹名称按服务商提供的名称填写。
登录方式分“密码／客户端授权码”和“OAuth2 访问令牌”。Outlook／Microsoft 365 配置较复杂；授权码教程内有完整步骤，工具旁的“获取微软 OAuth2 Token”仅适用于微软邮箱。需要自己的已注册应用客户端 ID；访问令牌过期后手动更新，本版不自动登录或刷新令牌。组织邮箱可能需要管理员许可，不能靠换一个普通密码绕过。
代理可选直连、系统代理、HTTP CONNECT 或 SOCKS5。系统代理先在 v2rayN 等客户端开启；手动代理填写实际主机和端口，常见主机为 127.0.0.1，10808 仅示例。无需为显式 IMAP 代理开启 TUN。此设置仅用于该邮箱的连接测试和收信，不设置 AI API 代理。代理失败会报错，不会偷偷直连；不支持 PAC 或需要账号密码的代理。保存后再测试连接。

4. 选择 AI
进入“AI 服务”，选择 API、Codex 或 DeepSeek Harness。
API：填服务商提供的基础地址、API Key 和模型名。支持 Chat Completions 兼容接口，会补齐 /chat/completions；优先使用 HTTPS，本机 localhost 可用 HTTP。Key 与基础地址绑定，换地址要保存对应 Key，模型名必须与服务商提供的一致。密钥留空仅保留当前地址已有的 Key。
Codex：先安装、登录并配置本机 Codex。软件自动使用已登录应用提供的 Codex；请先在 Codex 验证能正常使用。
DeepSeek Harness：使用用户已安装并配置好的 dsh；可“检测安装／检测 Harness”或“浏览”选择实际启动器，留空时自动查找。不捆绑、不自动下载 Harness 或它的运行时；登录、模型和网络先在 Harness 配好。
保存 AI 设置，再测试连接。测试会发少量内容，可能消耗额度。邮件正文及可读取附件文字会交给所选 AI；不要将敏感材料发给不适合处理它的服务。报告、问答和重试使用当前选择的语言与 AI 设置，不会自动发送邮件。

5. 监听、间隔、开机启动和退出
主窗口“开始监听／暂停监听”控制自动检查；“立即检查”请求一次检查，不必连续点击。每个新账号第一次检查只记录收信起点，不分析整个旧收件箱。恢复后补查暂停、断网或关机期间收到且仍在所选文件夹的新邮件；移动或删除的邮件可能无法读取。
自定义检查间隔填写整数秒数 10–86400，随本页统一“保存”；默认 60 秒。无新邮件不调用 AI，但失败的待处理任务可重试；暂停监听会等正在进行的操作安全结束。
“通用设置 → 启动与运行”可选登录 Mac 时显示菜单栏图标。关闭窗口后仍在菜单栏监听；通过 Dock、菜单或 ⌘Q 退出会停止监听并保存暂停状态，重新打开后点击“开始监听”。

6. 系统通知与免打扰
“开启／暂停系统通知”在监听按钮旁，仅控制系统通知，和监听开关相互独立。关闭通知后仍收信、总结并保存报告。在“通用设置 → 通知与免打扰”配置开关和免打扰时间，点击保存。
使用 24 小时 HH:mm 格式（如 22:00、08:00）。使用电脑本地时间，可跨午夜；起点包含、终点不包含；开启后相同起止时间表示全天免打扰。静音期间不积攒通知，恢复后不会补发。系统级通知权限或专注模式仍可能阻止显示。

7. 报告目录、阅读、搜索和筛选
在“通用设置 → 报告保存位置”点击“浏览……”选择可写目录。
新报告路径为“所选目录／收件邮箱地址／日期／From 发件邮箱地址／主题-收到时间.md”，缺失目录自动创建。例如“邮件／123@456.com／2026-10-21／From 234@567.com／example-11-53.md”。本版启动时会整理能识别收件邮箱的旧报告，同时保留报告对应的原邮件、附件和对话关联；无法识别的旧报告仍可阅读。
报告目录只保存可阅读的报告文件；原邮件、附件索引等 JSON 数据存放在软件的私有数据目录，不会混在报告文件夹里。升级会自动整理旧版配套 JSON，报告正文不变。卸载时选择保留邮件报告，也会保留其私有原邮件数据，便于重装后继续阅读和提问。
报告列表的“报告树”开关可切换文件夹式逐层浏览：先选邮箱，再选日期，再选发件人，最后选择报告。每个文件夹显示匹配报告数，可点“上一级”或路径返回；关闭后恢复平铺列表。搜索与筛选对整个报告集合生效，树中仅显示匹配结果。更换目录不会移动旧报告；要继续查阅旧文件，可在原文件夹打开或将目录切回。报告标题显示原主题，收到时间另列；文件名仍含时间。Markdown 支持标题、列表、表格等，旧 TXT 仍可读。
选择左侧报告在右侧阅读；可“打开报告”、打开报告文件夹，Mac 还可“复制原文”（复制报告源文本，不是发送邮件）。搜索覆盖本机保存的主题、正文、发件人和附件名，不是搜索整个远端邮箱。可按收到日期、发件人、有无附件组合筛选；无结果时清除搜索或重置筛选。
拖动总结和问答之间的分隔线自由调整高度。旧报告没有原邮件索引时，阅读报告仍可用，但依赖原邮件的问答、草稿、重新总结会报错；不会把 AI 总结当原文。

8. 重新总结、邮件问答与上下文
“重新总结”按当前语言与 AI 设置重新处理原邮件和原附件；成功后替换当前报告，失败保留旧报告，可能再次收费。
“对邮件提问”：在选中报告下方输入问题，可用“添加附件”选择额外参考文件，再发送。每封邮件分别保存完整对话，可恢复；额外文件与原邮件附件会区分。事实依据使用保存的原邮件正文及提取的原附件内容，AI 报告、以前的回答和压缩摘要不作为事实证据。缺失原邮件会明确报错，不会凭总结猜测。
长对话会压缩较早轮次并保留最近内容；压缩不是逐字记忆，完整记录仍在本机。重要数字、条款或原话请引用核对。原材料和最近对话超出上下文预算时拒绝发送并给出提示，不会悄悄截断后装作读完。文件过大或无法读取也会说明。不打开邮件内链接，不执行宏或邮件中的指令。

9. 回复与原文
选中报告，点击“回复”生成邮件回复；选择正式、简短或友好，可补充要求，生成后可编辑并保存草稿。发送前选择“邮箱与检查”中已添加的邮箱，点击“发送”后会显示发件邮箱、收件人、主题和完整正文；核对后再点“确认发送”，邮件才会通过服务商 SMTP 发出。生成可能收费；发送操作不可撤回。当前 Outlook OAuth2 令牌只有 IMAP 权限，不能用于 SMTP 发送；自定义 IMAP 服务器也不会猜测其 SMTP 地址。附件需在邮箱客户端中另行添加。
“原文”单独显示本机保存的来信正文、发件人、收件邮箱及附件名称；没有保存原邮件时会明确提示，不会拿 AI 报告冒充原文。

10. 附件增强与报告溯源
选中报告，点击“报告溯源”查看实际提供给 AI 的原邮件及附件文字。
正文以 [mail.body]、附件以 [attachment.N] 引用，PDF 页码只在实际提取到 [page:P] 时引用 [attachment.N, page:P]。来源页面显示实际供给 AI 的文字；引用仅是定位，不代表 AI 推断已获独立验证。原有报告不会自动增加来源；重新总结才使用新规则。提取文字可能截断，会显示限制；没有读取的附件不会当作已知事实。
图片及扫描 PDF 优先用本机原生 OCR：Mac 用 Apple Vision／PDFKit，Windows 用系统 OCR／PDF，不需要正常用户另装 Python。Windows 缺少适用的 OCR 语言支持时可能不可用；图像清晰度影响效果。原生 OCR 不可用时，可使用本机已有 Tesseract，扫描 PDF 的备用路线还需要 pdftoppm，不自动下载外部工具。识别在本机进行，提取的文字随后随分析交给所选 AI。
每附件最多 20 MB、约 100000 字符、每份 PDF 最多识别 20 个扫描页面；Office 主要提取文字，不执行宏、不还原图片排版。加密、损坏、不支持或超时会明确标为未读；OCR 不等于理解图片里的所有内容。

11. 黑名单、白名单和垃圾邮件
在“邮箱与检查”的“屏蔽邮件”选择黑名单或白名单。黑名单跳过列表内发件人；白名单只总结列表内发件人，空白名单会跳过全部新邮件。按完整邮箱地址匹配、不区分大小写，不能用域名或 * 通配符代替。可手动添加地址、“批量选择”已有发件人、逐项移除；规则共用于所有账号，只影响今后处理，不删除旧报告或服务器邮件。
修改名单或垃圾邮件选项后，点击本页底部的“保存”，规则才会生效。
勾选“不总结垃圾邮件（部分邮箱可能不支持）”后，只使用明确的服务器标记、垃圾头或文件夹，不调用 AI 猜测。只检查当前配置的文件夹；服务商不提供标记时无法可靠识别。
展开“已屏蔽”可按发件人查看记录。“总结此邮件”和批量总结仅对本次绕过屏蔽，使用当前 AI／语言，仍可能收费；失败保留记录。“删除此记录”或批量删除只清除本机屏蔽记录，不删除邮箱原件。

12. 历史邮件补总结
在“通用设置 → 邮件工具 → 历史邮件补总结”选择要补处理的邮箱。
选择日期范围后先“查询／查看待处理数量”，看清数量再确认；只预览不调用 AI。确认才把邮件加入队列，运行监听后逐封处理，可能产生费用；已总结的邮件按本地索引／可用完成记录跳过，旧版缺索引时无法保证完全去重。仍遵守黑白名单和垃圾邮件设置。日期按邮箱服务器的收件日期筛选；预览一小时过期，超过 10000 封请缩小日期范围。此功能不改动、标已读或删除原邮件。

13. 费用与用量
进入“AI 服务 → 费用单价”。币种、每百万输入／输出 Token 单价用于估算费用，不是用量或限额；点击“查看用量记录”查看只读的调用次数、Token 和费用记录，用“刷新”更新。单价随本页唯一的“保存”一起生效。“通用设置 → 邮件工具”也可查看记录。
仅记录安装本版后发生的调用；查看调用次数、Token 和未知用量次数。填输入／输出每百万 Token 单价和三字母币种（如 CNY、USD），保存后按当前模型／服务地址记录估算；费用使用每次调用时的价格，不追溯重算。换模型或服务商要核对对应单价。未配置价格或接口不返回用量时显示未知，不当作免费；Codex／Harness 订阅和本地工具无法推算实际账单。不同币种不相加。服务商控制台账单才是费用凭证。

用量记录分行显示“输入 Token”和“输出 Token”，并带千位分隔。输入是发给 AI 的原邮件、可读附件及对话，输出是 AI 返回的内容；这些数量不是用量限额。缺失的用量或费用明确显示“未知”，不代表免费；“用量未知的调用”为 0 也不能证明未返回的某项 Token 或费用已知。已知数字可能仅覆盖部分记录。

费用分别显示“上游返回费用”和“本地估算费用”，各有覆盖调用数；同一次调用有上游费用时，不再计入本地估算，另外显示费用未知的调用数。不同币种分别显示，不能直接相加；本地单价仅用于没有上游费用的调用。账户余额需点击“查询账户余额”手动获取，仅支持官方 DeepSeek 和 OpenRouter；其他服务或非 API 分析方式会明确提示不支持。查询不会生成 AI 内容，也不会在后台自动进行。余额属于整个服务商账户，可能包含其他软件或网站的使用，不能算作本工具剩余额度；查询失败不代表余额为零。

自动采集上游费用并非适用于所有服务商：官方 OpenRouter 返回的 usage.cost 记为 USD；兼容接口需要在 usage.cost 与 cost_currency 中明确给出费用及币种，或返回含 amount／currency 的 cost 对象。没有明确金额和币种时，仍使用已配置的本地估算，或显示未知。OpenRouter 的 /credits 余额接口需要管理权限，普通推理 Key 可能返回 403；这不代表 AI 调用不可用，也不建议仅为查询余额就把本工具的推理 Key 换成管理 Key，可到服务商控制台查看余额。没有权限、认证失败、未保存 Key、无法读取凭据和超时会分别提示。

14. 诊断导出与常见错误
使用“通用设置 → 邮件工具 → 导出诊断包”，可指定 ZIP 文件位置。
选择保存位置后得到 ZIP，内容只含版本、系统、脱敏状态和有限的错误类别／阶段，不含密钥、邮箱地址、服务地址、主题、正文、附件、聊天、原始日志或文件路径。分享诊断包时另写系统版本、操作步骤和错误发生时间；不要再附密码。
登录认证错误：先核对完整邮箱、客户端授权码、IMAP 开通状态及高级登录用户名。连接超时／TLS：核对服务器、端口、代理是否开启及系统时间。AI 测试成功而大邮件失败：查看具体错误、模型额度／上下文和文件读取限制，别反复点击产生重复请求。文件权限错误：用“浏览……”选择可写文件夹，勿保存到只读镜像。任何失败都应保留已有邮件与可恢复任务。

15. 语言、更新、卸载和帮助
在“通用设置 → 界面语言”选择简体中文、English 或 Español。
未安装的目标语言会先询问是否下载；确认后下载，取消或失败保留原语言。语言切换立即生效，新的报告／草稿／回复使用当前语言，旧报告不会自动翻译。产品英文名为 Email Assistant，西文名为 Asistente de correo electrónico。
在顶部“帮助 → 检查更新”或“通用设置 → 软件更新”操作。
自动检查每小时进行；只提示更新，不自动安装。手动“检查更新”也可使用。下载在应用内显示进度、来源和取消；中断后可重试／继续，安装前校验 SHA256 与大小，不合格禁止安装。安装时等邮件操作结束；保留配置和报告。Mac 更新失败尝试恢复旧应用；Windows 通过更新安装程序并保留失败信息，未确认成功不要当作已升级。下载或检查失败时可用“前往 GitHub 下载最新版”覆盖安装。安装过程中不要强制关机。
“通用设置 → 卸载 → 卸载邮件小秘书……”停止后台并进入卸载选择。
保留邮箱及 AI 配置、保留邮件报告是两个独立固定文字开关：开＝保留，关＝删除。关闭报告保留会二次确认，仅处理软件可识别的报告及索引，其他文件和用户自选根文件夹保留；配置保留不等于保留聊天历史、缓存和用量记录，重要资料卸载前另行备份。
顶部“帮助 → 使用指南”打开本文；“如何获取授权码？”打开服务商详细教程；“关于邮件小秘书”显示版本和芯片类型。语言包已安装时优先打开当前应用自带新版指南，避免沿用旧语言包过时说明。

Codex 模式：在 AI 服务选择 Codex，点“查找 Codex”，或浏览选择命令行程序，然后保存整页设置。查找只填写路径，不会自动保存。Windows 商店与 npm 安装均可检测；Mac 支持 Codex 和 ChatGPT 内置命令行组件。
